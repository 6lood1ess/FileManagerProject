# Групповой проект FileManager

## Описание задания

Разработать приложение для управления файлами с тремя функциями - организация файлов, шифрование файлов и резервное копирование файлов. Программа должна использовать архитектуру MVC, применить паттерн Singleton для управления ключами шифрования, паттерн Facade для упрощения интерфейса для пользователей и паттерн Memento для восстановления файлов до предыдущих версий.

## Описание работы с Git

Ветка main изначально содержит README.md с описанием постановки задачи и файл .gitignore для сохранения только полезных данных. Все мерджи обязательно проходят ревью через пулл-реквест. Правила нейминга выбраны следующим образом:

1. **main** - ветка для хранения стабильного кода. Мердж Тим-лидом через пулл-реквест после код-ревью.
2. **feature** - ветки для хранения стабильного кода бизнес-задачи. Мердж через пулл-реквест и код-ревью.
3. **wip-feature** - ветка для хранения нестабильного кода бизнес-задачи и любых промежуточных процессов разработки (при необходимости).
4. Если реализацией одной бизнес-задачи занимается несколько человек, то в именах веток ниже feature допускается явное указание имени разработчика, например `ivanov.ivan_wip-feature_module-name`.
5. В случае нарушения нейминга пулл-реквест отклоняется без ревью кода.

## Бизнес-задача №1. Организация файлов

Пользователи должны иметь возможность организовывать файлы в папке: сортировать по дате изменения, перемещать файлы определённого расширения в другую папку, получать статистику по папке (количество файлов, общий размер, распределение по расширениям), а также автоматически группировать файлы по типам в подпапки.

**Структурный паттерн для применения** - это паттерн **Facade**, который будет использоваться для упрощения интерфейса работы со сложной файловой системой. Внутри фасада будут скрыты подсистемы сканирования, перемещения и подсчёта статистики. Пользователю будут доступны только простые методы.

**Ответственный:** Дедушев Павел  
**Ветвь бизнес-задачи:** `feature_organization-facade`

## Бизнес-задача №2. Шифрование файлов

Пользователи должны иметь возможность шифровать и расшифровывать файлы с использованием симметричного алгоритма AES-256. Для безопасного хранения мастер-ключа в приложении используется глобальная точка доступа к единственному экземпляру менеджера ключей.

**Порождающий паттерн для применения** - это паттерн **Singleton**, который будет использоваться для управления глобальным ключом шифрования. Класс `EncryptionKeyManager` будет иметь приватный конструктор, статическое поле `_uniqueInstance` и публичное свойство `Instance`, обеспечивающее создание только одного экземпляра на всё приложение. Потокобезопасность достигается с помощью `lock` и double-check locking. Этот паттерн гарантирует, что ключ шифрования будет единым для всех операций шифрования и расшифрования.

**Ответственный:** Смушков Кирилл  
**Ветвь бизнес-задачи:** `feature_encryption-singleton`

## Бизнес-задача №3. Резервное копирование и восстановление файлов

Пользователи должны иметь возможность создавать резервные копии файлов (сохранять состояние до изменений), а затем восстанавливать файлы из этих копий. История резервных копий позволяет откатывать файл к предыдущим версиям в порядке LIFO (последним сохранён - первым восстановлен).

**Поведенческий паттерн для применения** - это паттерн **Memento**, который будет использоваться для сохранения и восстановления состояния файлов без нарушения инкапсуляции. Паттерн реализуется тремя участниками:
- **Memento** (`FileBackupMemento`) - хранит состояние файла (содержимое, путь, размер, хеш, время создания);
- **Originator** (`FileOriginatorForBackup`) - объект, состояние которого сохраняется; умеет создавать Memento и восстанавливаться из него;
- **Caretaker** (`BackupHistoryCaretaker`) - управляет историей бэкапов (хранит стек Memento).

Этот паттерн позволяет пользователям отменять изменения файлов и возвращаться к предыдущим версиям, реализуя функциональность "отката" (Undo).

**Ветвь бизнес-задачи:** `feature_backup-memento`
